# Analysis Guardrails（分析护栏 — 教学版）

> 简化自 `domain-aware-data-analyst/references/analysis-guardrails.md`，专为课堂示范场景。AI 在每一步示范时必须遵守，并在 Checkpoint 中考察学生是否理解。

## 1. 永远先检查的四种风险

### 泄漏（Leakage）
出现以下任一就高度怀疑：
- 特征在结果发生后才可见（如"是否最终违约"作为"会不会违约"的特征）；
- 特征是标签计算的一部分；
- 聚合特征跨越 train/val 时间边界；
- 同一实体（学号/病人/订单）在 train 和 val 同时出现。

→ Checkpoint 必考。

### 粒度错位
- 事件级变量直接并到个体级；
- 家庭/班级/医院当成独立样本；
- 多表 join 忽略 1:N 膨胀。

### 样本偏差
- 数据只覆盖"被记录下来的人"；
- 某些群体更容易缺失或晚录入。

### split-before-fit 违反
- `StandardScaler().fit(X_all)` 再切分 → test 信息漏进 scaler；
- 用 `SimpleImputer` 在切分前填全量均值；
- 自动特征选择在切分前看了 y。

→ 这是教学场景的高压线，AI 示范时必须示范正确做法。

## 2. baseline 规则

- 必先做最简单可解释的 baseline，再决定是否升级；
- baseline 至少回答："不用复杂模型时，我们已经知道了什么？"；
- 若复杂模型仅边际提升，应保留可解释方案——并把这件事讲给学生听。

## 3. 评估规则（按任务）

### 分类
默认不只报 Accuracy。按场景看：
- Precision：误报代价高
- Recall：漏报代价高
- F1：两者都重要
- PR-AUC：正类稀少时
- Calibration：概率要进阈值决策时

### 回归
- MAE：贴近日常误差
- RMSE：放大大误差
- 残差模式（系统偏差、漏斗形异方差）

### 聚类
- 每群规模 + 稳定性 + 可命名 + 与决策对应

### 高风险场景（教育/医疗/金融/招聘）
即便课堂 demo，也要让学生看到子群体差异检查与 calibration 的重要性。

## 4. 复现要求

- 固定随机种子（`random_state=42`）；
- 记录主要库版本（`sklearn.__version__`、`fastai.__version__`、`gensim.__version__`）；
- 记录数据快照名 / 文件名 / 时间戳；
- 切分索引可保存为 npy / csv 以便复跑。

## 5. test 集纪律

- test 只做一次终评；
- 误差分析、阈值调整、特征回改、任务回改 → 用 validation / CV out-of-fold；
- 反复看 test 调参 → 等价泄漏。

→ Checkpoint 5 / 7 必考。

## 6. 表述规则（讲给学生听）

| 证据类型 | 允许说 | 禁止说 |
|---|---|---|
| 描述统计 | "样本中 X 比例更高" | "总体上必然 X" |
| 相关分析 | "X 与 Y 相关" | "X 导致 Y" |
| 预测模型 | "可用于预测/排序" | "证明了机制" |
| 观察数据 | "提示一种解释" | "已经证明因果" |

学生最容易把"重要特征 = 原因"——AI 示范时必须当场打断这种说法。

## 7. 何时建议"不建模"

出现以下情况时，AI 应主动停步并把这一决策讲给学生听：
- 标签定义不可信；
- 真实可用特征极少且全是事后变量；
- 样本量不足以支撑稳定验证；
- 训练/应用场景明显错位。

→ 跳到 Step 10 给反馈报告，标注"本次任务不适合建模"。
